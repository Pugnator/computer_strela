# Embedding and compatibility

The primary API is [include/strela/system.h](../include/strela/system.h). Create an opaque machine with strela_machine_create(NULL) for the default timing profile. It begins paused so a caller can write RAM, supply CDD constants, mount cards or tape zones, select a PC, and set the control-stop switch. Resume and call strela_machine_run_for_us or strela_machine_step. Read strela_machine_state for PC, omega, last instruction, stop reason, display words, counters, simulated microseconds, pending group and batch counts, and tape events. Use strela_machine_reason_name to display the underlying stop cause even when the operator state is paused. Edit RAM, constants, the PC, the check switch or media only while the machine is paused or stopped. After a budget-limited run, pause first. strela_machine_step also executes one boundary from paused state and leaves it paused if still running. strela_machine_reset(start) resets execution, timers, positions and punched output, retaining RAM, constants and mounted media, and leaves the machine paused at start. strela_machine_constant_source tells whether a CDD address is built in, operator-supplied or unknown.

The opaque API owns its card deck and tape zones. File load methods parse a complete replacement before mounting it. Save methods write a temporary file and replace the target after success. Snapshot save/load covers RAM, constants, media, cursor state, pending events, timing profile and operator state. Failed snapshot load leaves the current machine unchanged. Destroy the machine when finished.

The older [include/strela.h](../include/strela.h) remains source compatible. Its visible strela_t layout is retained; strela_init/strela_destroy and strela_step still work. strela_step completes an entire repeated group for legacy callers, whereas the opaque API steps at each group or batch element. The old card callback interface remains usable, but owned decks are the supported replay path. The implementation is split across machine, word, instructions, timing, media, snapshot and system modules; [src/strela_compat.c](../src/strela_compat.c) records the compatibility boundary.

Legacy code must call strela_destroy before reinitializing a strela_t with allocated media. Direct mutation of the visible struct can bypass validation and is discouraged for new integrations. Writes to RAM cell 0000 are ignored; CDD writes use strela_set_constant before execution.

CLI: strela_run listing.txt [start-octal] [step-limit] [dump-octal] is preserved. The explicit run, resume and inspect commands, image formats and exit statuses are in [the contract](../specs/001-strela-system-emulator/contracts/cli-and-images.md).
